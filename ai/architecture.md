# 项目结构与设计原则

## 目录职责

应用代码采用 `src/` 布局，位于 `src/linkforge/`：

| 目录 | 职责 |
|---|---|
| `ui/` | 桌面界面、配置保存与后台线程 |
| `application/` | 应用生命周期、任务检测与调度 |
| `platforms/` | 平台实现，目前主要为学习通 |
| `browser/` | 浏览器接口与 Playwright 适配 |
| `observation/` | 网页状态捕获与观察 |
| `action/` | 结构化浏览器动作执行 |
| `agent/` | Browser Agent 契约、编排与交互循环 |
| `llm/` | 模型接口与服务商适配 |
| `config/` | 配置模型 |
| `log/` | 日志配置 |

测试位于 `tests/`，组织规则见 [testing.md](testing.md)。项目说明与设计资料位于 `docu/`。
更细的职责说明见 [各个文件责任说明](../docu/各个文件责任说明.md)，具体实现以当前代码为准。

## 运行入口与模块边界

- [gui.py](../src/linkforge/gui.py) 是桌面入口，[main.py](../src/linkforge/main.py) 是开发运行入口；
  两者通过 [composition.py](../src/linkforge/composition.py) 组装生产应用。
- `LinkForgeApplication` 管理浏览器生命周期并通过 `PlatformRuntime` 接入平台；
  学习通的检测器、处理器及单次运行状态由 `platforms/chaoxing/runtime.py` 组装。
  新平台接入沿用这一边界，不在通用应用层添加平台 DOM 或平台专用分支。
- 当前课程流程由 `application/TaskRunner` 检测并分派任务。
  `agent/BrowserAgentLoop` 是独立的观察、决策、执行循环；修改课程处理时先确认实际调用链。
- GUI 通过 [RuntimeWorker](../src/linkforge/ui/worker.py) 在 `QThread` 中创建并运行应用，
  通过 Qt 信号更新界面。浏览器操作留在所属工作线程，不在 UI 主线程执行长任务。
- 停止是协作式请求：启动等待阶段、视频状态轮询或任务边界退出，并由应用清理浏览器。
  `TaskHandler.run_interruptibly` 向支持中断的处理器传递停止回调，其余处理器默认在任务边界退出。
  修改停止、关闭窗口或异常处理时，保留资源清理路径，不将强制终止线程作为常规停止方式。
- `TaskRunner` 通过可选的 `TaskRecovery` 接口委托平台处理任务失败；学习通恢复器在任务前保存
  页面快照，验证身份后暂缓失败视频或跳过问题卡片。暂缓记录与完成记录分开，只在本次运行生效。
  `RunIssue` 只保存脱敏摘要，由应用持有并在工作线程结束时交给 GUI 汇总；导航失败或身份不明确
  时保留错误退出，不将“已跳过”作为课程完成证据。
- 视频播放期间的手动换页由 `ChaoxingNavigationMonitor` 确认连续稳定的课程快照并同步续播位置，
  再通过 `TaskPageChangedError` 让运行器重新检测；该控制流不表示任务完成，也不进入失败暂缓或跳过流程。
  恢复器同样先检查已验证的页面切换，避免检测与执行之间的换页竞争导致跳过用户选择的新内容。
- 独立作业页由 `assignment_page.py` 校验受支持路由、主页面表单与题目数量；`assignment_handler.py`
  复用测验的截图、作答及回读流程，使用主 frame 作用域代替课程卡片 iframe。单份作业完成后结束
  本次流程，不进入课程目录导航或故障跳卡片。提交通过正常 UI，浏览器基础设施只被动观察同源、
  指定路径和表单条件的 JSON 响应；响应正文不写入日志，保存响应与最终提交分开处理。

## 设计约束

- 新功能放入职责最贴近的现有模块；需要拆分时创建小而聚焦的模块，避免扩大无关文件。
- 平台相关 DOM、识别和处理规则放在 `platforms/`，通用应用层保持平台无关。
- 浏览器、LLM 等外部服务放在可替换的适配器后，便于隔离依赖和测试。
- 能够通过确定性规则完成的操作优先使用规则；大模型用于确实需要模型判断或生成的环节。
- 任务完成与节点跳过依据可验证的页面状态；未知模块、目录橙色计数（包括 `0`）或到达目录末尾
  不作为完成证据。改变完成判定时同步更新对应测试与用户说明。
