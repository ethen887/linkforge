# LinkForge

LinkForge 是一个基于 Python、Playwright 和大模型的浏览器自动化项目。

目前提供桌面 GUI，主要用于处理学习通课程中的视频、文档、测验和讨论任务。同时保留独立的 Browser、Observation、Action 和 Agent Loop 模块，方便开发者扩展浏览器工作流。

能够通过确定性规则完成的操作优先使用规则；大模型主要用于测验识别与讨论内容生成。

## 项目状态

项目处于早期开发与真实页面验证阶段，支持源码运行、Windows x64 便携包和中文 Setup 安装包构建。
候选包采用 PyInstaller onedir 并内置 Chromium，Setup 使用 Inno Setup 包装完整程序目录；
用户无需安装 Python 或其他开发环境。当前尚未公开发布经过完整安装验收的桌面发行包。

开发者构建和验收步骤见 [Windows 便携版构建与验收](docu/Windows便携版构建与验收.md)。

中文 Setup 安装包的构建步骤见 [Windows 安装版构建与验收](docu/Windows安装版构建与验收.md)。
安装版默认按当前用户安装，并将日志保存到 `%LOCALAPPDATA%\LinkForge\logs`。

目前主要验证 Windows 桌面使用流程。自动化测试包含本地浏览器集成测试和 GUI 测试，但不代表所有课程页面、模型服务或桌面系统均已兼容。

当前不保证任意学习通课程都能完整自动处理。遇到不支持的模块或无法确认的页面状态时，程序会停止并记录错误。

## 当前功能

| 功能 | 说明 |
|---|---|
| 桌面 GUI | 配置课程地址、模型服务、API Key 和浏览器用户目录，查看运行状态与日志 |
| 配置保存 | 保存常用 GUI 配置，通过系统凭据库保存 API Key |
| 学习位置记忆 | 确认进入下一张课程卡片或下一章节后，自动更新并保存课程地址，下次启动从最近页面继续 |
| 登录状态复用 | 使用独立浏览器用户目录保存登录状态；需要登录时等待用户手动操作 |
| 视频处理 | 播放视频，检查播放进度及任务完成状态；播放停滞时有限重试暂停后继续，恢复无效则停止并记录状态 |
| 文档处理 | 处理已支持的 PDF 和电子书阅读器，通过实际滚动与页面状态检查进度 |
| 测验处理 | 支持单选、多选、判断题，校验答案格式与选中状态，通过正常页面控件提交 |
| 独立作业 | 支持直接打开学习通独立发布的作业答题页，逐题作答、核验并提交，无需先进入视频课程目录 |
| 讨论处理 | 根据讨论标题和教师问题生成评论，并通过页面提交 |
| 课程导航 | 切换卡片，按目录顺序前进，支持跨章节导航 |
| 已完成任务跳过 | 根据目录中明确的绿色完成标记跳过已完成节点 |
| 错误诊断 | 对 UNKNOWN 状态进行有限重试，输出脱敏结构信息 |
| 安全停止 | 视频播放期间可直接停止，无需等待视频完成，退出时清理浏览器资源 |

内置模型服务配置包括阿里云百炼、DeepSeek、Gemini、OpenAI 和 Anthropic，可在 GUI 中填写模型名称。

测验处理需要所选模型和接口支持图片输入。提供配置入口不代表所有模型均已通过实际兼容性验证。

## 安装与运行

需要：

- Python 3.12 或以上版本（CI 与本地 uv 环境均使用 3.12）。
- Git 和 uv。
- Playwright Chromium。
- 可用的模型服务 API Key。

以下命令以 PowerShell 为例：

```powershell
git clone https://github.com/ethen887/linkforge.git
cd linkforge

uv sync --locked
uv run playwright install chromium
uv run python src/linkforge/gui.py
```

Linux 环境安装浏览器时，可能还需要系统依赖：

```bash
uv run playwright install --with-deps chromium
```

## 构建 Windows Setup 安装包

开发者可以用一条命令，从源码生成可分发的 `setup.exe`。

**前置条件：**

- Windows x64 和 64 位 Python 3.12。
- 已安装 uv，并已克隆本仓库。
- 已安装 Inno Setup 7；安装程序的中文语言文件需保留。
- 构建时可以联网下载依赖与 Chromium。

**在仓库根目录的 PowerShell 中执行：**

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_installer.ps1
```

**无需先手动生成 `LinkForge.exe`。** 这个脚本会依次完成：

1. 按 `uv.lock` 同步依赖，准备内置 Chromium。
2. 用 PyInstaller 生成 `LinkForge.exe` 及完整依赖目录。
3. 运行生成程序的离线自检；失败时中止构建。
4. 用 Inno Setup 将完整程序目录编译成中文 Setup，并生成 SHA-256 校验文件。

**成功后，到 `dist/` 目录获取安装包。当前版本输出为：**

```text
dist/
├── LinkForge-v0.1.0-beta.1-windows-x64-setup.exe
└── LinkForge-v0.1.0-beta.1-windows-x64-setup.exe.sha256
```

文件名中的版本号随项目版本变化。构建流程还会生成同版本便携 ZIP；给安装版用户分发 `setup.exe` 即可。
最终用户双击安装包，按向导安装后从开始菜单或桌面快捷方式启动。

脚本会自动查找 Inno Setup 编译器。使用自定义安装位置时，可以指定 `ISCC.exe`：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_installer.ps1 -IsccPath "C:\Tools\Inno Setup 7\ISCC.exe"
```

在尚未安装 LinkForge 的 Windows 测试账户中，可执行安装验收：

```powershell
uv run --locked python scripts/verify_installer.py dist/LinkForge-v0.1.0-beta.1-windows-x64-setup.exe
```

该命令会在独立目录中临时安装、自检、覆盖安装并卸载；已有安装时会拒绝执行。
干净 Windows 环境、跨版本升级和真实课程仍需另行验收。详细说明见
[Windows 安装版构建与验收](docu/Windows安装版构建与验收.md)。

## 使用方法

1. 在浏览器中进入学习通课程，复制实际课程学习页面的地址；也可复制独立发布的作业答题页地址。
2. 在 LinkForge 中填写课程地址，选择模型服务商和模型，输入 API Key。
3. 保留默认浏览器用户目录，或选择一个专供 LinkForge 使用的目录，以便后续复用登录状态。
4. 点击“开始运行”。
5. 如果浏览器显示登录页面，请手动完成登录。
6. 程序确认课程页面就绪后开始检测和处理任务。

点击“停止”或关闭窗口时，视频任务会在下一次状态轮询时响应，无需等当前视频播放完成，随后清理浏览器资源。未完成的视频仍保持未完成状态；再次启动时按平台记录的进度继续。模型请求等待期间也可取消：关闭本地连接并等待网络任务清理，不必等满 300 秒；测验及独立作业取消后不继续选择答案或提交。断开本地连接不保证服务商立即停止生成或停止计费。其他类型的任务仍在任务边界响应停止。

界面和文件日志会显示当前题号、模型请求开始、首个流式数据块时间及每 15 秒的进度摘要，包括数据块数、答案/推理字符数、服务商返回的 token 用量和安全的失败原因（如超时、限流/额度不足或 HTTP 402 余额不足）。每个请求有本地产生的编号，模型名称只记录指纹；不记录密钥、接口完整地址、题目截图、提示词、答案或推理正文。部分服务商不会返回推理或用量信息，缺失的计数显示为 0，不能据此认定模型没有推理或没有计费。首个数据块也可能只包含角色信息，不能等同于首个答案字符。这些信息用于区分未收到数据与持续输出，不代表可以查看服务商内部的排队或推理过程；流式显示也不会自动缩短模型本身的处理时间。

独立作业目前支持 `/mooc-ans/mooc2/work/dowork` 页面中的单选、多选、判断题，以及下述已适配的大题编辑器。程序检查真实题目结构，逐题截图发送给已配置的视觉模型，再通过正常页面控件填写、回读核验和暂存。整份作业处理后交给用户检查并手动提交，不把“保存成功”或窗口关闭当作提交完成，也不代表整门课程已完成。遇到验证码、尚未支持的题型或无法确认的暂存结果时会停止，需用户检查。

章节测验和独立作业每次实际选择或取消一个选项，并回读确认后，会检测“暂时保存”等明确的暂存按钮。有唯一可见且可用的按钮时点击一次；没有按钮时照常继续，按钮不唯一或不可用时在日志中提示并跳过。多选题每次增删选项后也会暂存；已选状态无需修改时不会重复点击。暂存后重新获取题目并核验当前及此前答案，避免重绘后继续使用旧元素；暂存本身不会重新调用模型。独立作业额外核对正常 UI 发出的保存响应，明确失败时停止，未收到确认时在日志中提示检查。暂存与最终提交分别处理，保存成功不计作作业完成，也不会代替最终提交。

再次运行时，单选和判断题若已有一致、有效的选中状态，会保留已有答案，跳过截图和模型请求，从未答题继续。依据的是实际选项状态，不依赖题号导航的颜色；页面上手动选择的答案也会保留。多选题的非空状态可能是上次逐次暂存的中间结果，因此仍需模型核验；题型不明确或选中状态冲突时不会直接跳过。保留已有答案不代表验证其正确性；独立作业在全部答案回读核验并确认暂存后交给用户提交。

独立作业中的简答、计算题提供大题草稿流程，第一版适配已观察到的 UEditor 正文 iframe 和 TEX 公式窗口。每道空白大题的截图会发送给配置的视觉模型，要求按正式考试答卷格式完成所有小问，保留必要列式、代入计算、单位及最终结论，避免“解题分析”等讲解口吻；长推导拆为较短公式。录入前规范化已知公式命令的多余反斜杠，保留 aligned 等环境中的正常换行；缺失命令反斜杠或错误控制字符不能直接填写。程序通过正常输入及 TEX 确认按钮录入，等待公式图片加载并核对公式数据后暂存，再继续下一题。已有大题会将题目截图、当前正文和公式数据发送给配置的模型，先简短判断是否完整、切题；可保留则跳过重做，需要重做则先生成并校验完整答案，再通过正常键盘操作清空旧内容、覆盖录入和暂存。判断或生成失败时保留原文；模型等待期间用户修改内容时暂停，不覆盖新输入。AI 判断仅作初步检查，最终仍需用户审核。模型返回格式不合法时，日志显示具体校验类别；大题页面状态异常会显示程序内的固定暂停原因；仅对可修复的 JSON、字段或公式分隔符格式错误，将原答案发送给同一配置模型进行一次格式修复，不重新解题，修复仍失败则暂停。空答案、截断响应、超长内容和不支持的公式命令不会自动修复。暂存需要明确成功回执，并重新核验正文和选项；题干核验排除编辑器工具栏的字体、字号等变化，公式保存核验比较解码后的数据而非百分号编码写法；公式失败、编辑器未知或保存未确认时交还人工检查，不自动改成 LaTeX 源码填入正文。暂不支持其他编辑器、作图、附件和章节测验中的大题；开始前请关闭已打开的 TEX 窗口。

录入长答案时，点击 TEX 前先滚动到编辑器容器起点，让 UEditor 工具栏退出顶部吸附，再定位按钮，避免吸顶工具栏持续被作业页顶栏遮挡。正文输入或打开公式窗口出现浏览器交互错误时，先回读正文、公式和窗口状态：确认已经生效则继续，内容完全未变且没有公式窗口时重新定位并重试一次；部分写入、状态不一致、无法回读或重试仍失败时保留草稿并暂停。清空旧内容失败时不自动重试。日志区分输入正文与打开 TEX，并显示遮挡、元素失效或超时等固定错误类别，不记录底层错误中的页面内容和链接。

整份作业首次暂存完成后，程序自动审核所有大题：向配置的同一模型发送原始题目截图和题干、编辑器首尾视图、完整正文及公式数据，检查公式渲染、各小问的完整性、计算和单位、题目数据以及正式答卷口吻。生成内容中的成对行内/展示公式会先在本地拆分为文字与 TEX 段落，去掉公式块外层的成对分隔符或数学代码围栏，不改动数学内容；无需为这些可确定处理的排版问题再请求模型。无法配对的公式不猜测边界。实际网页正文仍包含 LaTeX 源码或“按常见取值”等措辞时，不能直接视为审核通过。审核问题按题号和轮次记录；仅重做未通过的题，并携带此前反馈重新生成、覆盖、暂存和复审，最多自动重做两轮。日志只记录固定问题类别，自由文本反馈仅在本次运行内存中供模型修正，不记录答案正文。用户在审核或重做等待期间修改内容、审核结果无效或达到上限时暂停并保留浏览器，不无限调用模型。自动审核会增加模型请求和图片用量，最终仍需用户检查。

独立作业无论是否包含大题，都按整份作业连续处理，全部处理、确认暂存并完成大题自动审核后界面显示“等待检查草稿”，不会自动提交。浏览器保留供用户检查、修改并手动提交；填写或核验失败时显示“草稿未全部确认暂存”，仍保留浏览器。界面与文件日志显示当前题号及大题录入段落进度，不记录答案正文。检查期间不会继续自动作答或导航，点击“停止”或关闭 LinkForge 后才清理浏览器。重新启动会重新检查已有大题；部分草稿不再因非空而直接跳过；检查会话结束不表示平台作业已提交。

视频播放期间，可以在当前课程标签页中手动选择其他章节或卡片。LinkForge 会等待新页面稳定后重新检测并处理当前选择的内容，同时更新续播位置。主动换页不会被记为视频故障，也不会把原视频标记为完成或暂缓；原视频保持平台记录的状态。快速连续切换时，以最后确认稳定的页面为准，点击停止仍优先结束运行。

任务遇到可恢复的问题时，会先记录问题并尝试继续：失败的视频在本次运行中暂缓，继续同一卡片的后续视频、文档等内容；其他任务失败时，在确认页面身份和导航目标后跳过当前卡片剩余内容。跳过不会修改平台完成标记，也不代表课程全部完成，下次运行仍会重新处理未完成内容。

界面日志和文件日志会记录问题位置、任务类型、原因及处理结果。点击停止、关闭窗口或运行结束后，会弹出本次问题汇总，提示哪些内容需要检查或补做。浏览器关闭、页面身份无法确认或无法可靠导航时，运行仍会停止，并保留此前的问题清单。

安装版运行日志保存在 `%LOCALAPPDATA%\LinkForge\logs` 中；便携版保存在 EXE 同级 `logs/` 中；
源码运行保存在项目根目录的 `logs/` 中。
可点击“打开日志文件夹”定位本次日志。反馈问题时，请提供错误类型、复现步骤以及经过检查和脱敏的日志片段。
便携版须完整解压到有写入权限的位置，不要单独移动 EXE 或删除 `_internal`。

## 已知限制

- 当前生产课程工作流主要支持学习通，其他平台尚未接入。
- 不支持所有学习通模块或测验题型，填空、简答等题型尚未纳入当前处理范围。
- 测验答案由模型生成，不保证正确率。
- 学习通页面结构变化可能导致识别、导航或提交失败。
- 浏览器登录状态可能失效，需要重新登录。
- 部分处理记录仅在单次运行中保存，不具备完整的持久化断点恢复能力。
- 当前尚未实现可靠的整门课程完成判定。到达最后一个目录节点时，可能因缺少完成证据而停止并报错。
- 文档处理默认不设总阅读时长上限，但仍保留加载、进度和页面状态检查。
- 尚未提供经过完整安装验收的桌面发行包或自动更新功能。

目录中的橙色计数，包括数字 `0`，不会被当作完成证据。未知模块也不会被自动跳过。

## 配置与隐私

- GUI 的常用配置通过本机设置存储保存。
- API Key 使用系统原生凭据库保存，不提供明文文件回退。
- 凭据库不可用时，本次运行仍可继续，但 API Key 可能无法保存。
- 浏览器用户目录包含登录状态，应保留在本机，不要提交到仓库或分享给他人。
- Windows 默认浏览器用户目录为 `%LOCALAPPDATA%\LinkForge\browser-profile`，更新便携程序不会替换此目录。
- 测验截图和讨论上下文会发送给配置的模型服务，用于生成答案或评论。

反馈或提交 Issue 时，请勿提供 API Key、Cookie、Token、账号密码、完整课程链接或未经脱敏的日志和截图。

```text
├── ui/             桌面界面、配置保存与后台线程

├── platforms/      平台实现，目前主要为学习通
├── browser/        浏览器接口与 Playwright 适配
├── observation/    网页状态观察
├── action/         结构化动作执行
├── agent/          Browser Agent 与交互循环
├── llm/            模型接口与服务适配
├── config/         配置模型
└── log/            日志配置

tests/              单元测试与本地集成测试
docu/               项目说明文档
```

平台相关的 DOM、识别和处理规则放在 `platforms/` 中，通用应用层保持平台无关。

## 开发与测试

使用仓库中的锁文件安装依赖：

```powershell
uv sync --locked
```

提交前执行：

```powershell
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run mypy src
```

自动化测试应能在没有真实课程账号和模型凭据的情况下运行。

## 参与开发

欢迎报告问题、提出需求、改进文档，也欢迎开发自己需要的功能并提交 Pull Request。

请先阅读 [贡献指南](CONTRIBUTING.md)，通过 Issue 讨论需求和实现方案，再从最新 `main` 创建功能分支。

基本流程：

```text
创建或选择 Issue
→ 明确范围和验收标准
→ 创建功能分支
→ 实现并测试
→ 提交 Pull Request
→ CI 与代码评审
→ 合并并清理分支
```
